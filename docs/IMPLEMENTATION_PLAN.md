# Student Workbench — 分阶段实施计划（TDD）

- 文档版本：0.3.0
- 路线：自研轻量核心，先验证最高风险，再完成端到端闭环
- 范围：P0 教务课程表、学习平台作业、统一课程关联、统一事项与项目进度管理
- 原则：垂直切片、测试先行、真实数据验收、每个阶段可运行

## 1. 实施策略

### 1.1 不按技术层分批

不采用“先写完整后端，再写完整前端，最后联调”的方式。每个阶段都交付可观察结果：

```text
可运行骨架
→ 学校数据真实进入收件箱
→ 本地与 GitHub 形成项目健康
→ 今日执行与同步中心闭环
→ MVP 硬化与验收
```

### 1.2 风险顺序

1. 教务/学习平台登录、页面结构、课程身份映射和同步归并。
2. 本地 Git 与 GitHub 数据的语义正确性。
3. 健康规则是否可解释、是否有行动价值。
4. 通用 UI、设置和体验完善。

Todo CRUD、主题、图表和 AI 不是最高风险，不能先占用核心验证时间。

### 1.3 TDD 循环

每个行为按以下顺序：

1. **Red**：写一个会失败的行为测试，说明输入、动作和可观察结果。
2. **Green**：写最小实现使测试通过，不提前加入下一阶段功能。
3. **Refactor**：在测试保护下移除重复和模糊命名，保持行为不变。
4. **Contract**：需要跨层时补 API/适配器契约测试。
5. **Walkthrough**：通过 UI 或真实命令观察结果，不能只以测试存在代替验收。

先测试领域规则，再测试适配器，最后测试页面；不是先写大量 mock 后补业务。

## 2. 阶段总览

| 阶段 | 交付目标 | 主要内容 | 阶段门禁 |
|---|---|---|---|
| S0 | 可运行骨架与契约 | 工程、迁移、API、路由、CI、fake 数据 | 前后端与测试链路可运行 |
| S1 | 教务课程表与学习平台作业进入统一课程和收件箱 | 内嵌登录、可选密码保存、两类适配器、课程身份映射、同步状态 | 真实教务/学习平台同步、课程关联与异常降级通过 |
| S2 | 项目进度与健康 | 生命周期、状态历史、项目待办、仓库、本地扫描、GitHub、健康规则 | 两个真实项目验收通过 |
| S3 | 今日执行与完整体验 | 学校/项目/手动事项汇总、计划、同步中心、设置、错误状态 | 四条核心 E2E 路径通过 |
| S4 | MVP 硬化与发布候选 | 安全、恢复、备份、性能检查、文档、构建 | PRD 全部 AC 通过 |
| P1 | 验证后的增强 | 自动同步、导出、通知、周报等 | 由真实使用结论排序 |

## 3. S0 — 可运行骨架与契约

### 3.1 实现内容

- 创建 `pyproject.toml`、uv 锁文件、前端 npm 锁文件。
- 固定 `TECH_STACK.md` 的版本基线，配置 Ruff、TypeScript、Vitest、pytest。
- 实现应用数据目录、日志脱敏、配置读取。
- 建立 Alembic 和第一版完整 schema migration。
- 实现 SQLite 外键、WAL、busy timeout 和事务入口。
- 实现 `/healthz`、`/bootstrap`、`/settings`。
- 实现本地 Host/Origin/自定义头写保护。
- 创建 React Provider、AppShell、路由、AsyncState 和 OpenAPI 类型生成。
- 配置 FastAPI 托管前端构建产物和 Vite 开发代理。
- 建立 `academic_fake`、`learning_fake` 和最小健康规则输入 DTO，但不接真实教务/学习平台。
- CI 运行后端测试、前端 typecheck/测试和构建。

### 3.2 先写测试

- 首次启动创建数据库，重复启动迁移幂等。
- SQLite 外键确实启用，唯一约束生效。
- 非允许 Origin 的写请求被拒绝。
- bootstrap 默认 `setup_completed=false`，完成后重启保留。
- OpenAPI JSON 可生成，前端类型生成命令可重复执行。
- `/` 能加载并显示空状态；`/setup` 可完成初始化。

### 3.3 完成标准

- 一条命令启动后端，一条命令启动前端。
- 本地使用模式能由 FastAPI 提供前端页面。
- 测试数据库与正式数据库完全隔离。
- 仓库内没有数据库、浏览器会话、token 或真实教务/学习平台 fixture。
- 骨架通过 CI，尚未宣称学校或 GitHub 接入完成。

## 4. S1 — 教务/学习平台接入、统一课程与收件箱

### 4.1 S1-A：教务/学习适配器契约与解析

#### 实现内容

- 定义共享 `PlatformAdapter` 登录/会话/挑战契约，以及 `AcademicAdapter`、`LearningAdapter` 和标准 DTO。
- 编写 `academic_fake`、`learning_fake`，覆盖正常、空数据、登录过期、结构变化、验证码挑战和 partial。
- 获取当前学校教务页面结构，编写 `academic_portal_v1`，只读取课程身份和课程表。
- 获取学习通实际页面结构，编写 `chaoxing_v1`，读取课程身份和作业。
- 将真实页面保存为**脱敏且最小化**的本地测试材料；只有确认不含个人信息后才能转为仓库 fixture。
- 实现平台与 SSO 域名限制。
- 实现“预期容器不存在 ≠ 空课程/空作业列表”。

#### 先写测试

- 教务 fixture 只产生课程身份和课程表，不产生 WorkItem。
- 课程表星期、时间、周次、单双周、自定义周次和地点映射正确。
- 学习平台 fixture 产生课程身份和作业，必填来源字段完整。
- 容器存在但无数据时返回空列表；容器缺失或选择器失效时抛 `PlatformStructureChanged`。
- 登录页/重定向登录页抛 `PlatformAuthRequired`。
- 遇到未配置域名停止访问。
- 缺失外部 ID 时按契约处理，不生成随机外部 ID。

#### 门禁

- 两类 fake 全场景通过。
- 真实教务适配器能读取课程和课程表，真实学习通适配器能读取课程和作业。
- 不能只用 fake 通过就宣称教务或学习平台接入完成。

### 4.2 S1-B：内嵌登录、可选密码保存与外部回退

#### 实现内容

- 在工作台实现内嵌登录向导，通过本地 API 提交账号密码和验证码挑战，Playwright 在本地驱动真实平台。
- 不使用 iframe 直接嵌入平台网站；复杂 SSO、特殊二次验证或适配器不支持时回退到独立可见 Chromium。
- 每个连接使用独立持久化浏览器目录。
- 提供“仅本次登录”和“保存密码并自动填充”两种模式。
- 平台账号标识存 SQLite，密码通过 keyring 以 `platform:{connection_id}` 为键保存到系统凭据库。
- 自动填充只允许作用于连接配置的平台/SSO 域名，其他域名立即停止。
- 实现登录状态、登录输入、验证码挑战、取消、密码清除、会话清除和外部回退 API。
- 验证码/二次验证由用户在内嵌向导或外部页面完成，不实现验证码识别或绕过。
- 登录检测与会话过期处理，浏览器路径、日志和异常脱敏。

#### 先写测试

- 内嵌模式可完成账号密码和 fake 验证码挑战，不支持时能切换外部浏览器。
- 未开启保存时不创建平台密码凭据。
- 开启后密码只写入凭据服务，不出现在 SQLite、API 响应、浏览器持久化存储或日志。
- 自动填充只在允许域名发生，重定向到其他域名时不填入密码。
- 登录挑战响应不包含 Cookie，验证码提交后不出现在日志。
- 连接状态转换合法，取消后回到可配置状态，会话目录不能逃出应用数据目录。
- 过期会话映射 `needs_auth`，不是通用 500；密码失效与验证码挑战能由用户接管。

#### 人工验收

- 仅本次登录时，可在工作台内嵌向导输入账号密码并完成验证。
- 开启保存后可自动填充；复杂 SSO 能回退到外部浏览器，由用户接管。
- 重启后端后可复用会话；过期后能重新登录。
- 清除密码不清除会话，清除会话不删除密码；两者独立且都需确认。

### 4.3 S1-C：两类同步、统一课程映射与事务

#### 实现内容

- SyncExecutor、连接锁、SyncRun 持久化，教务与学习连接独立同步。
- 教务同步外部课程身份和课程表，不创建作业；学习平台同步外部课程身份和作业。
- 建立 `courses/course_identities/course_schedule_entries`，按 `(connection_id, external_id)` 幂等 upsert。
- 实现“学期 + 规范化课程名”精确匹配，教师消除歧义；唯一候选自动关联，歧义保持 unmatched。
- 支持人工关联、解除、创建新课程和忽略来源；改绑时同事务更新课程表归属和 WorkItem.course_id。
- 多个学习平台身份可指向同一课程，重复发布的作业保留各自身份，不自动去重删除。
- partial、failed、needs_auth、interrupted，来源缺失标记 `needs_review`，同连接重复同步返回现有 SyncRun。

#### 先写测试（核心）

1. 同一教务数据同步两次，课程身份和课程表总数不变。
2. 同一学习平台数据同步两次，课程身份和作业总数不变。
3. 教务同步不创建 WorkItem；学习平台首次 open→inbox，submitted/graded→done。
4. 后续 external_status 更新不覆盖 workflow_status，本地计划、优先级、备注和项目关联保持。
5. 唯一精确候选可 auto_exact，同名不同学期或同名歧义保持 unmatched。
6. 手动改绑后，该身份下课程表和作业一起换 course_id，其他来源不受影响。
7. 两个学习平台身份可关联同一课程，重复作业仍保留来源。
8. 结构解析失败不被当作零课程/作业，单课程失败产生 partial。
9. 全局认证失败保留旧数据，同连接并发只有一个活动 SyncRun。
10. 重启时 running→interrupted。

### 4.4 S1-D：课程映射、课程表与收件箱 UI

#### 实现内容

- `/settings/integrations` 教务/学习连接、内嵌登录、外部回退、同步和错误操作。
- 课程映射页展示外部身份、精确候选、歧义和手动关联。
- `/courses` 统一课程与周课程表，课程详情聚合教务课程表、各平台身份和跨平台待办。
- `/inbox` 筛选、事项详情、来源链接和本地计划编辑，学习平台课程归属由映射维护。
- 首次引导包含教务同步、学习平台同步和课程关联确认。

#### 先写测试

- 内嵌登录可提交 fake 凭据/验证码，复杂场景可切换外部浏览器。
- 登录失效时显示重新登录而非通用失败。
- 同步运行期间按钮防重，切换页面后可重新附着。
- 教务课程表不显示为待办，点击今日课程能定位相关课程待办。
- 歧义课程不被自动合并，改绑后课程表、收件箱和今日课程一起刷新。
- 外部字段只读，本地字段可编辑，编辑成功后相关查询失效。
- 后台刷新失败保留旧列表并显示过期提示。

### 4.5 S1 完成标准

- PRD 的 AC-01～AC-06、AC-13、AC-16～AC-18 全部通过。
- 使用真实教务数据完成至少两次课程/课程表幂等同步，使用真实学习通数据完成至少两次课程/作业幂等同步。
- 真实确认教务课程与学习通课程的统一关联，并用第二个 fake 学习平台验证跨平台聚合。
- 真实修改本地计划后再次同步，字段和课程映射保持。
- 真实会话失效、内嵌挑战、外部回退和网络失败均有可恢复 UI。
- 此阶段即可独立使用“教务课程表 + 学习平台作业 → 统一课程/收件箱”，无需等项目模块完成。

## 5. S2 — 项目进度管理

### 5.1 S2-A：项目生命周期、状态历史与项目待办

#### 实现内容

- 项目 CRUD 中 P0 所需操作、下一步和里程碑。
- 生命周期状态：`idea/planning/in_progress/blocked/waiting/on_hold/completed/cancelled/archived`，默认 `planning`。
- 当前 `status_reason/status_changed_at/resume_at`，状态变化自动追加 `project_status_history`。
- `blocked/waiting/on_hold/cancelled` 必须填写具体原因；`waiting/on_hold` 可设置恢复日期。
- 项目详情直接创建 WorkItem，自动关联 `project_id`，设置 `source_type=manual/item_type=task`，与统一收件箱复用同一服务。
- 项目 `next_action` 仅作为焦点摘要，只有用户显式操作才转换为项目待办。

#### 先写测试

- 九种生命周期状态展示和转换行为正确。
- `blocked/waiting/on_hold/cancelled` 缺少原因被拒绝；其他状态可正常保存。
- 每次状态变化追加历史，旧原因不被覆盖，当前状态时间正确更新。
- `idea/on_hold/completed/cancelled/archived` 返回 inactive 健康，不产生无活动提醒。
- 项目待办创建后 project_id、来源和类型正确，可通过 `project_id` 查询。
- 下一步不会自动生成待办，只有用户显式转换才通过 POST /work-items 创建带 project_id 的事项。
- 里程碑 done 设置 completed_at，恢复后清空。
- 无里程碑返回“未设置”语义，不计算 100%。
- 编辑下一步刷新 next_action_updated_at。

### 5.2 S2-B：本地 Git 扫描

#### 实现内容

- 本地路径校验和规范化。
- 只读 Git CLI 执行器、超时与错误映射。
- branch、dirty、ahead/behind、upstream、detached、最后提交。
- 本地快照追加和最新成功快照查询。

#### 先写测试（全部使用临时仓库）

- 干净仓库、脏工作树、暂存修改计数。
- 临时 bare remote 构造 ahead 和 behind。
- 无 upstream 时 ahead/behind 为 unknown，不误报 0。
- detached HEAD、空仓库、非 Git 目录、路径不存在。
- 扫描器不执行 fetch/pull/push/commit 等写命令。
- stderr 中可能存在的本地用户名和敏感 URL 不进入外部响应。

#### 门禁

- 在两个真实个人仓库扫描，结果与人工 `git status` 等命令一致。
- UI 明确 ahead/behind 的 remote-tracking ref 语义。

### 5.3 S2-C：GitHub 远端同步

#### 实现内容

- OS 凭据库 token 配置和状态 API。
- GitHub REST client、分页、超时、错误和限流。
- Issue 排除 PR、开放 PR、review requested、默认分支 checks、最近提交、里程碑。
- 远端快照和 GitHub 里程碑同步。
- 无 token 的公开仓库只读尝试与权限错误处理。

#### 先写测试

- 分页完整聚合。
- GitHub Issue 计数不包含 PR。
- pending/failure/success/缺失 checks 映射正确。
- 401/403/404/429/5xx 不伪造空快照。
- token 只从凭据服务读取，不出现在 DTO、日志和 API。
- 外部 closed 里程碑首次映射 done，后续不覆盖本地状态。

### 5.4 S2-D：健康规则与项目 UI

#### 实现内容

- 健康纯函数和原因 DTO，生命周期状态与健康等级分离。
- 只有 `planning/in_progress/blocked/waiting` 参与健康评估，其他生命周期返回 `inactive`。
- 最新成功快照选择、数据新鲜度和 unknown。
- 项目列表、项目详情、状态表单、状态历史、项目待办、健康原因、仓库卡片、里程碑编辑。
- 每个健康原因对应具体跳转或用户动作。

#### 健康规则表驱动测试

至少覆盖：

- `blocked` 项目为红并展示具体原因，`waiting` 项目为黄并展示等待对象/事件。
- 逾期未完成里程碑为红，已完成逾期不报警。
- 默认分支失败检查为红，pending 不当作失败。
- dirty/ahead/behind 分别为黄。
- `planning/in_progress` 且无下一步为黄；其他状态不要求下一步。
- `planning/in_progress` 超过无活动阈值为黄。
- `idea/on_hold/completed/cancelled/archived` 为 inactive，不继续产生无活动提醒。
- 快照陈旧为黄，参与评估但缺失全部成功快照为 unknown。
- 红色优先于黄色；unknown/inactive 不被当作 green。
- 无风险且输入完整为 green。
- 同一输入重复计算结果完全一致。

#### 前端测试

- 五种健康等级均同时显示文字与图标，inactive 与 unknown 文案不同。
- 状态原因必填规则和状态历史展示正确。
- 项目待办可在详情页新增并立即刷新详情、收件箱和今日查询。
- 原因能定位到仓库、里程碑、下一步或同步入口。
- 失败快照不会把最近成功数据替换为零值。
- 项目扫描完成后相关查询刷新。

### 5.5 S2 完成标准

- PRD 的 AC-07～AC-10、AC-14 通过。
- 两个真实项目展示本地和远端状态。
- 至少人工制造 dirty、ahead、CI 失败和无下一步，健康原因与规则一致。
- 所有健康提示都有原因、证据和时间，没有生产力分数。
- 此阶段可独立使用“项目 → 风险处理 → 重新扫描”。

## 6. S3 — 今日执行与完整用户闭环

### 6.1 实现内容

- `GET /dashboard/today` 统一聚合学习平台作业、项目待办和其他手动事项的逾期、今日计划、临近未计划、受阻分组，单独汇总项目风险，并根据教务课程表返回 `classes_today` 及每门课的待办统计。
- 项目待办显示项目名称和生命周期状态；暂停或完结项目中已明确计划今天的事项仍保留并标记状态。
- 今日页行动按钮与项目风险定位，项目待办变更同步刷新项目详情、收件箱和今日。
- 设置时区、临近截止天数、快照过期和无活动阈值。
- 同步中心统一学校与 GitHub 最近运行。
- 首次引导项目步骤。
- 所有页面的加载、空、错误、过期状态。
- 可访问性和键盘流程检查。

### 6.2 先写测试

- 本地时区跨日边界正确，UTC 日期不直接代替本地今日。
- 截止与计划分别进入正确分组。
- 教务课程表按设置时区和 term_start_date 生成 classes_today，不生成 WorkItem；缺少学期起始日期时只提示确认，每门今日课程的相关待办统计和跳转正确。
- 学习平台作业、项目待办和其他手动事项使用同一分组规则并显示正确归属。
- done/dismissed 不出现在待执行分组。
- upcoming_unplanned 不包含已经计划的事项。
- 暂停/完结项目中已明确计划今天的待办仍显示项目状态；inactive 项目本身不进入健康风险。
- 只有需要处理的红色项目风险进入今日。
- 修改设置后今日和健康查询失效并刷新。
- 同步失败时今日仍展示本地数据并增加 data_warnings。

### 6.3 核心 E2E

1. **课程路径**：setup → 内嵌 fake 登录 → 教务同步课程表 → 学习平台同步作业 → 确认课程关联 → 今日课程定位待办 → 计划今天 → 开始 → 完成。
2. **项目路径**：创建项目 → 临时 Git 仓库 → 扫描 → 风险定位 → 修复临时仓库 → 风险消失。
3. **恢复路径**：教务/学习平台会话过期 → 旧数据可编辑 → 内嵌或外部重新登录 → 同步恢复 → 本地计划和课程映射不变。
4. **项目状态与待办路径**：项目改为 waiting/blocked → 填写原因 → 状态历史追加 → 新增项目待办并计划今天 → 今日完成 → 项目详情与收件箱一致。

### 6.4 完成标准

- PRD 的 AC-15 通过，四条 E2E 均通过真实 FastAPI + 临时 SQLite + 浏览器。
- 核心操作不依赖手动刷新页面。
- 无学校、无项目、同步为空、同步失败等状态文案准确。
- 今日页能回答“现在先处理什么”，而不是全部数据的简单堆叠。

## 9. 测试数据与 fixture 管理

### 9.1 教务与学习平台

- `academic_fake` 使用显式课程表、登录挑战和异常场景 ID；`learning_fake` 使用显式课程、作业、登录挑战和异常场景 ID，不依赖随机数据。
- 教务 fixture 只包含课程身份与课程表，学习平台 fixture 只包含其课程身份与作业，不能混造数据。
- 真实页面先本地脱敏，移除姓名、学号、Cookie、token、密码、验证码和个人 URL 参数。
- 仓库 fixture 只保留解析所需最小 HTML 结构。
- 真实账号和会话只存在本机应用数据目录，第二个学习平台聚合测试使用额外 fake 连接。

### 9.2 Git

- 每个测试创建临时工作树和临时 bare remote。
- 测试 Git 身份只在临时仓库 local config 设置。
- 测试结束清理临时目录由测试框架处理，不触碰用户仓库。
- 产品扫描器只读；测试准备阶段可以写临时仓库，两者代码分离。

### 9.3 GitHub

- 使用小型手工 JSON fixture 和 HTTPX MockTransport。
- 覆盖分页、空 checks、部分权限、rate limit。
- 真实 GitHub 验收使用专门选择的仓库，不上传 token 到 CI。

## 10. P1 — MVP 验证后的实施候选

P1 不按文档顺序机械执行，而按 P0 观察结果排序。

### P1-A 数据保障（建议优先）

- 手动 JSON 导出和数据库备份按钮。
- 导出 schema 版本、恢复校验、敏感信息提示。
- 测试导出→新数据库→恢复后的核心数据一致。

### P1-B 自动同步

- 在 SyncExecutor 上增加本地调度。
- 连接级间隔、退避、应用休眠后的过期处理。
- 不自动处理验证码，不无限重试认证失败。
- 测试同连接不并发、失败退避和重启恢复。

### P1-C 通知

- 临近截止、同步失败、红色项目风险。
- 通知去重和可配置静默。
- 不重复提醒已经处理的风险。

### P1-D 教务/学习信息与 GitHub 扩展

- 教务通知、考试安排、学习平台通知等只读接入，按实际内容选择独立读模型或 WorkItem，不强行都转成作业。
- 用户选择性导入 GitHub Issue 为 WorkItem。
- 保持本地执行状态不被后续同步覆盖。

### P1-E 项目排期

- 在项目详情增加排期视图，展示里程碑 `due_at` 和项目待办 `due_at/planned_start_at/planned_end_at`。
- 支持按周/月查看、调整计划日期、识别排期冲突和无计划待办。
- 拖拽只修改本地计划，不修改教务/学习平台或 GitHub 原始数据。
- 先实现项目时间线，不扩展成完整课程日历。

### P1-F 确定性周报

- 汇总项目状态历史、完成事项、里程碑变化、仓库风险、遗留和下周交付。
- 项目状态原因直接来自 `project_status_history`，不让 AI 猜测。
- 无 AI 也可生成；提交数只作为证据链接，不作为评分。

## 11. P2 暂排方向

### P2-A AI 辅助复盘（非 MVP）

- 以确定性周报为输入，由用户主动点击“生成 AI 复盘草稿”，不自动生成或自动修改计划。
- 支持用户配置的 API 模型或本地模型；API key 使用 OS 凭据库，模型提供方与输出设置可替换。
- 用户先选择可发送的数据范围，默认排除平台密码、验证码、Cookie、token、完整仓库代码和无关个人信息。
- 发送前展示数据预览，输出必须由用户确认后才能保存为周报；保留原始确定性数据供对照。
- 不用 AI 自动评价生产力、自动安排全部日程或处理验证码。

### P2-B 其他方向

- 更多教务适配器、更多学习平台适配器和其他教务内容。
- 完整日历、ICS 导入导出。
- 课程笔记与复盘知识库。
- PWA 安装与明确的离线策略。
- 桌面托盘或单命令开机启动。

多用户、云同步、自动答题/提交、自动识别或绕过验证码、自动 Git 写操作仍不进入默认路线图。

## 12. 每个开发任务的 Definition of Done

- 行为测试先写并证明在实现前失败。
- 实现满足 PRD 边界，没有顺手加入后续功能。
- 领域、适配器、API、UI 的测试放在正确层级。
- 错误路径和空状态与成功路径同时完成。
- 日志和响应不包含秘密。
- OpenAPI/前端生成类型同步更新。
- 文档与实际行为一致。
- 本地相关测试通过，核心路径有实际页面或命令验证证据。
